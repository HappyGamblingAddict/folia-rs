This document is a status snapshot for continuing the Rust rewrite of Folia
1.21.11. It is not a claim of parity. The project is still a partial server.

---

## Goal and architecture

Goal: rewrite Folia to Rust while keeping real, unmodified Bukkit/Paper `.jar`
plugins working.

Architecture:

- Rust owns the server, world, protocol, game logic, and tick loop.
- The core has no Java runtime dependency. An embedded JVM starts lazily only
  when `plugins/` contains at least one `.jar`; it exists solely for plugin
  API/classloading/events and the compatibility bridge. With no jars (or
  `FOLIA_DISABLE_PLUGINS=1`) the server runs fully native.
- Folia 1.21.11 decompiled sources are the reference at
  `C:/Users/austr/Downloads/rustfol/decompiled`.
- Java oracle data is captured from a real Folia server, then embedded or used
  in differential tests.

Current size is still far below the 744k-line Folia codebase. Major gameplay
systems remain missing.

## What works

### Protocol and sessions

- Status JSON, ping/pong, legacy ping.
- Offline-mode login (`online-mode=false`).
- Captured 1.21.11 configuration registries.
- Join Game, player position, keepalives.
- Live chunk streaming: a 13×13 column around the player is generated by the
  noise generator and saved back to the region files (stamped
  `folia:written`), so later joins load it instead of regenerating. Stored
  chunks are served when `world/level.dat` exists or the chunk is stamped;
  `FOLIA_LOAD_STORED=1` forces every stored chunk. Newly visible columns are
  sent when the player crosses a chunk border, and columns beyond one chunk of
  the radius are unloaded. No tickets or cross-player dedupe yet; missing
  columns are generated on scoped worker threads, and a cold 169-column join
  measures about 1.9 s in release on the probe machine.
- A player logging in with their feet inside a solid block is lifted to the
  surface of that column (the captured spawn is `y = -60`, above bedrock).
- Player movement parsing and gzip-NBT playerdata persistence, including
  playerdata fields the server does not model (kept verbatim via
  `PlayerSession::extra`).
- `PlayerJoinEvent` through the Java bridge.

### Crafting and smelting

- `crafting.rs` matches the shipped recipe catalog with 1x1–3x3 shaped
  patterns (CraftingInput-style tight crop, mirror, item tags/alternatives),
  shapeless multiset rules, and vanilla's last-sorted-recipe-id priority.
  `CraftingGrid::craft` consumes one item per occupied slot, preserves slot
  components, and returns a `CraftOutput` that deposits through
  `inventory::add_stack`.
- `FurnaceState` models furnaces, blast furnaces, smokers, and campfires with
  input/fuel/result slots, the common-fuel burn table, per-recipe cook times,
  output stacking, exact XP accumulation, and extraction. Stonecutting and
  smithing transforms are one-shot operations; smithing copies base components
  onto the result. Special/decorated-pot/trim/opaque recipes fail with
  `CraftingError::UnsupportedRecipe` instead of crafting nothing.
- Tests: `tests/crafting.rs` (19) plus 5 focused lib tests.

### Block simulation

- `tick.rs` implements vanilla update flags, a deterministic chunk-grouped
  neighbour queue, scheduled ticks with priority/delay/dedup, and seeded random
  ticks. `tick_world` runs neighbour, scheduled, and random ticks in that order
  every server tick.
- `fluid.rs` adds scheduled water/lava flow: source/flowing/falling levels,
  5-tick water vs 30-tick lava delays, drop-off, downward priority, slope search
  toward holes, water source conversion, waterlogged placement, and drain.
- `redstone.rs` adds `SignalGetter` strong/weak queries, wire 0..15
  propagation/dedup through the neighbour queue, lever toggling, and button
  press with a scheduled release.
- Tests: `tests/ticks.rs` (10), `tests/fluids.rs` (7), plus focused
  `--lib tick`/`--lib fluid`/`--lib redstone` unit tests.

### Plugin bridge

- Lazy embedded JVM, only started when `.jar` plugins are present.
- No Java required for the native server, worldgen, protocol, or tick loop.
- Unmodified Bukkit/Paper plugin loading, events, commands, scheduler bridge.
- `World`/`Block` proxies: `getBlockAt`, `getType`/`setType`,
  `getLocation`, `getHighestBlockYAt`, `getBiome`, sky/block light, chunks,
  `BlockData`/`BlockState` subsets. Reads use the shared overworld storage and
  do not generate missing terrain.
- `Player` proxy: world, location, inventory, game mode, messages, teleport,
  health/food/saturation. `setGameMode` reaches a live session; the rest is
  persisted through `PlayerSession` playerdata (live-session sync is pending).
- `PlayerInventory`/`ItemStack` proxies: slots 0-35, type/count/damage,
  display name, lore, unbreakable. `new ItemStack(...)` works through a
  `RegistryAccess`/`InternalAPIBridge` service shim; armor/off-hand and
  enchantment persistence remain open.
- Host-callable `BlockBreakEvent`, `BlockPlaceEvent`, and
  `PlayerInteractEvent` with cancellation. Vanilla break/place handlers still
  bypass the event bus until `join.rs` is wired.
- Example plugin exercises the world, player, inventory, and event APIs.
  `FOLIA_BRIDGE_SELFTEST=1` also fires the three events from Rust and checks
  their cancellation results.
- `FOLIA_DISABLE_PLUGINS=1` forces native-only startup even when jars exist.

  slot, enchantability, repairable set, fire resistance, and rarity.
  `item_prototypes.rs` validates the catalog, looks items up by name/id, and
  supplies `defaults_for`/`apply_defaults` patches for the modeled
  `item_components` subset. The breaking code still uses its built-in
  `ToolMaterial` table and writes `max_damage` on first wear; wiring it to the
  catalog is a follow-up.
- Block behaviour metadata is generated (`block_state_behaviour.tsv.gz`) and
  covers hardness, light, solidity, motion, friction, and fluids. Breaking uses
  it, but loot tables, item entities, Unbreaking/Fortune/Silk Touch, and the
  block-damage overlay packet are still open.
- Item stacks carry the component patch model and the prototype catalog. The
  `attribute_modifiers`/`potion_contents`/`tool` network codecs,
  `HashedStack` hashing, and a Java component NBT/packet fixture are still
  missing. The plugin bridge persists type/count/damage/name/lore/unbreakable;
  enchantments, PDC, and container contents do not cross the bridge yet.
- Generated chunks are at 98.75% class / 95.80% exact-name agreement, not
  100%.
- Chunk generation is ~15.7 s for 49 debug chunks, of which carver replay is
  ~2.7 s; still too slow for a production login path.
- The server falls back to seed `0` if `level.dat` is missing.
- Non-overworld dimensions are not generated.

### Gameplay

- Block breaking validates dig start/stop/abort, break time, tool tiers,
  efficiency/haste/fatigue, creative instant break, and durability. Drops use a
  deterministic common-block table and go into the inventory because item
  entities do not exist yet; real loot tables, Fortune/Silk Touch, Unbreaking,
  block-break effects, and adventure `can_destroy` are missing.
- Redstone is not ported.
- Redstone is partial: wire, lever, and button are ported; repeaters,
  comparators, torches, observers, pressure plates, lamps, pistons, and other
  components are not. Fluids flow on scheduled ticks but lava fire/quenching
  and block-destruction drops are not modeled.
- Entity AI, goals, pathfinding, combat, and general damage are not ported.
  Players now take void damage, die, and respawn at world spawn; fall, fire,
  hunger, and projectile damage are still missing. The new `LivingEntity`
  model handles raw health/death but is not wired into sessions, and it does
  not yet apply armor, enchantments, absorption, knockback, or damage types.
  Metadata covers indices 0-9 only, initial non-default spawn metadata is not
  sent, and there is no Java-captured metadata/equipment packet fixture.
- Entity tracking range/culling and player physics corrections are not ported.
- Crafting/smelting exist as a tested state model, but there are no crafting or
  furnace menus, click handling, recipe book/advancement unlocks, brewing, or
  block-entity persistence. Special/decorated/trim recipes are explicit
  unsupported errors.
- No block entity behavior, containers beyond the player inventory, or other
  smelting-adjacent menus.
- No lighting updates after block changes beyond full chunk light payloads.
- No online-mode encryption or Mojang authentication.
- No NMS/CraftBukkit compatibility beyond the minimal bridge.

### Protocol/API

- Captured configuration registries are replayed; they are not generated from
  Rust registries.
- Login is offline-mode only.
- Plugin API coverage now includes bootstrap, events, commands, scheduling,
  world/block read/write, player identity/vitals/game mode/teleport,
  player inventory, item meta (name/lore/damage/unbreakable), and the three
  cancellable block/interact events. Still missing: live-session sync for
  health/food/inventory/teleport/messages, live event dispatch from
  `join.rs`, armor/off-hand slots, enchantment/PDC persistence, entities,
  services, `PluginManager` queries, and NMS/CraftBukkit shims.
- No 1:1 Folia region/threading behavior yet.
- The native terminal console supports `help`, `list`, `ops`, `op`, `deop`,
  `gamemode`, and `stop`; operators persist in `run/ops.txt`. There is no
  Minecraft command tree, tab completion, or Bukkit console dispatch yet.

`FOLIA_MAX_TICKS` stops the server after a fixed number of ticks.
