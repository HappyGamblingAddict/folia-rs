---

## Goal and architecture

Goal: rewrite Folia to Rust while keeping real, unmodified Bukkit/Paper `.jar`
plugins working.

Architecture:

- Rust owns the server, world, protocol, game logic, and tick loop.
- The core has no Java runtime dependency. An embedded JVM starts lazily only
  when `plugins/` contains at least one `.jar`; it exists solely for plugin
  API/classloading/events and the compatibility bridge. With no jars (or
  `FOLIA_DISABLE_PLUGINS=1`) the server runs fully native.
- Folia 1.21.11 decompiled sources are the reference at
  `C:\Users\austr\Downloads\rustfol\decompiled`.
- Java oracle data is captured from a real Folia server, then embedded or used
  in differential tests.

Current size is far below the 744k-line Folia codebase. Major gameplay systems
are still missing.

## What works

### Protocol and sessions

- Status JSON, ping/pong, legacy ping.
- Offline-mode login (`online-mode=false`).
- Captured 1.21.11 configuration registries.
- Join Game, player position, keepalives.
- Live chunk streaming: a 13×13 column around the player is generated by the
  noise generator and saved back to the region files (stamped
  `folia:written`), so later joins load it instead of regenerating. Stored
  chunks are served when `world/level.dat` exists or the chunk is stamped;
  `FOLIA_LOAD_STORED=1` forces every stored chunk. Newly visible columns are
  sent when the player crosses a chunk border, and columns beyond one chunk of
  the radius are unloaded. No tickets or cross-player dedupe yet; missing
  columns are generated on scoped worker threads, and a cold 169-column join
  measures about 1.9 s in release on the probe machine.
- A player logging in with their feet inside a solid block is lifted to the
  surface of that column (the captured spawn is `y = -60`, above bedrock).
- Player movement parsing and gzip-NBT playerdata persistence, including
  playerdata fields the server does not model (kept verbatim via
  `PlayerSession::extra`).
- `PlayerJoinEvent` through the Java bridge.

### Feature framework

- `crates/folia-core/src/worldgen/feature/mod.rs` ports the framework shape:
  `Feature`, `FeaturePlaceContext`, `ConfiguredFeature`, `PlacedFeature`,
  `FeatureLevel`, the chunk-bounded `WorldGenRegion`, and the 11
  `Decoration` generation steps in vanilla order.
- `FeatureData::vanilla()` loads the embedded `feature_data.json`, normalizes
  bare dump keys to `minecraft:` ids, and validates all 224 configured, 258
  placed and 65 biome feature lists at load time.
- Implemented feature types: `no_op`, `tree`, `fallen_tree`, `ore`,
  `scattered_ore`, `random_selector`, `random_patch`/`flower`, `simple_block`,
  `block_pile`, `block_column`, `multiface_growth`, `vegetation_patch`, and
  `waterlogged_vegetation_patch`. 134 of 224 configured features execute;
  every other type loads as `Unsupported` and `place()` returns an
  `UnsupportedFeature` error rather than silently doing nothing.
- `worldgen/feature/vegetation.rs` ports the ground-cover batch with inline
  nested placed features and the shipped state providers: simple, weighted,
  randomized-int, noise, noise-threshold, dual-noise, and rotated. Provider
  draws follow vanilla order (`simple` draws nothing). Nested placements are
  predicate-only because every shipped patch uses `block_predicate_filter`;
  unsupported nest types make the parent explicitly unsupported. Vegetation
  patch positions use Java `HashSet` bucket order.
- Feature tests cover deterministic replay for a seed, different-seed divergence,
  chunk/vertical write bounds, no-op behavior, decoration ordering, definition
  counts, tag values, loud unsupported errors, provider draw order, shipped
  patch parsing, patch success/failure, block pile/column truncation, multiface
  attachment, and waterlogged patch behavior.
- `worldgen/feature/placement.rs` types every placement modifier and
  `IntProvider`/`HeightProvider`, and executes the six world-free modifiers
  plus `biome` with vanilla draw order. `PlacedFeature::placement_positions`
  chains them and returns `PlacementFailure` for unported ones.
- `worldgen/biome_zoom.rs` ports `BiomeManager`: SHA-256 seed obfuscation,
  the LCG fiddled-distance search over the eight quart corners, tie keeps the
  first. `BiomePlacementWorld` implements the `PlacementWorld` trait
  (`biome_at`, `biome_has_placed_feature`) over `BiomeSampler` and the loaded
  biome feature lists.
- Coverage from the shipped data: all 888 placement modifiers execute; the remaining P2.2 gap is a Java position fixture
  (`heightmap` 83, `block_predicate_filter` 12, environment scan 9,
  count-on-every-layer 8, noise counts 10, surface
  relative 3, one `clamped_normal` offset).
- `worldgen/feature/ore.rs` ports `minecraft:ore` and
  `minecraft:scattered_ore` with all 30 + 2 shipped configs, exact target
  states, and the four referenced block tags. Placement is tested directly.
  Generator wiring is intentionally off until feature-RNG parity; enabling it
  lowers the exact-name fixture from 92.09% to 89.06%. `OreVeinifier` remains
  unported.
- Wired into generation: `WorldGenerator::apply_decorations` runs the supported
  `underground_decoration`, `vegetal_decoration`, and `top_layer_modification`
  features after carvers, using a chunk-backed `FeaturePlacementWorld`.
  `underground_ores` stays off. Oak/birch trees generate in forest/plains/birch
  chunks; spruce/pine use layered foliage, dark oak uses its 2x2 branching
  trunk, forking acacia uses acacia foliage, fancy oak uses its limb trunk and
  clipped height, cherry uses its branch walk and hanging foliage, giant mega
  spruce/pine use a 2x2 trunk and crown foliage, mega jungle adds its branch
  walk and jungle foliage, `jungle_bush` uses the straight trunk with bush
  foliage, azalea pairs a bending trunk with random-spread weighted foliage,
  mangrove uses an upwards-branching trunk and waterlogged/muddy roots, fallen
  trees place a stump plus sideways logs, and leaf litter, beehives, vines,
  cocoa, alter-ground podzol, attached-to-leaves, attached-to-logs, creaking
  hearts, and pale moss decorate the supported shapes. Beehive occupants carry
  vanilla `bees` NBT, pale oak embeds `pale_moss_patch`, and
  `simple_random_selector`/`schedule_tick` execute; block-for-block Java tree
  fixtures and generator draining of the new region sinks remain open. Most
  remaining aquatic plants, vines, mushrooms/huge fungi, and structures are
  still unported.

## Known limitations / what is still missing

### World generation

- Ore and scattered-ore features are ported but not wired into generation;
  `OreVeinifier` is not ported.
- The P2.5 ground-cover types are ported, but most aquatic plants (seagrass,
  kelp, sea pickle, coral), vines, mushrooms/huge fungi, bamboo, structures, and
  special features are not. Selector branches that reference *placed* features
  (`pale_garden_vegetation`, `warm_ocean_vegetation`) still need a two-registry
  resolver.
- `simple_block.schedule_tick: true` and `simple_random_selector` now execute;
  the generator does not yet persist the ticks/block entities produced in
  `WorldGenRegion`, so pale forest flowers tick only once the caller drains the
  region. Vegetation noise providers use Xoroshiro-backed `NormalNoise`
  instead of Java's Legacy-seeded stream (see `DECISIONS.md`).
- Surface rules now use `BiomeManager`'s fuzzy zoomer for both the
  pre-extension biome and per-block `isBiome`/temperature checks when the
  configured generator seed is available; placement's `biome` filter uses the
  same zoomer. Direct `WorldGenerator::overworld` harnesses that never call
  `generator::configure` fall back to the chunk-local quart and can pin the
  seed with `build_surface_with_seed`.
- Frozen-ocean temperature and iceberg-melt decisions use the exact
  `biome_climate`/`PerlinSimplexNoise` tables. There is no captured Java
  frozen-ocean fixture yet, so these are pinned behavior tests rather than a
  differential chunk comparison.
- Paper's `generate-flat-bedrock` is supported via `server.properties`
  (`generate-flat-bedrock=true`); default `false` keeps the captured oracle's
  random bedrock depths. The real Paper YAML is not read yet.
- 134 of 224 configured feature types execute: `no_op`, trees, fallen trees,
  ores/scattered ores, random selectors, random patches/flowers, simple blocks,
  block piles, block columns, multiface growth, and vegetation patches. The
  rest fail loudly. Some world-dependent placement modifiers (non-ocean
  heightmaps, non-sapling predicates, environment scans, noise counts) still
  return explicit `PlacementFailure`s.
- Item stacks still carry only `item + count`; data components are not encoded
  (durability, enchants, container contents are not preserved).
- Block behavior metadata (hardness, light, solidity, tool rules) is not
  generated, so physics/lighting/breaking cannot be fully correct.
- Generated chunks are at 98.71% class / 92.04% exact-name agreement, not
  100%.
- Chunk generation is ~15.7 s for 49 debug chunks, of which carver replay is
  ~2.7 s; still too slow for a production login path.
- The server falls back to seed `0` if `level.dat` is missing.
- Non-overworld dimensions are not generated.

### Gameplay

- Redstone is not ported.
- Entity AI, goals, pathfinding, combat, and general damage are not ported.
  Players now take void damage, die, and respawn at world spawn; fall, fire,
  hunger, and projectile damage are still missing. The new `LivingEntity`
  model handles raw health/death but is not wired into sessions, and it does
  not yet apply armor, enchantments, absorption, knockback, or damage types.
  Metadata covers indices 0-9 only, initial non-default spawn metadata is not
  sent, and there is no Java-captured metadata/equipment packet fixture.
- Entity tracking range/culling and player physics corrections are not ported.
- No block entity behavior, containers beyond the player inventory, crafting,
  furnaces, etc.
- No lighting updates after block changes beyond full chunk light payloads.
- No online-mode encryption or Mojang authentication.
- No NMS/CraftBukkit compatibility beyond the minimal bridge.

### Protocol/API

- Captured configuration registries are replayed; they are not generated from
  Rust registries.
- Login is offline-mode only.
- Plugin API coverage is minimal: bootstrap, events, commands, scheduling,
  minimal player proxy. No full `World`, `Entity`, `ItemStack`, `Inventory`,
  scheduler, or service APIs.
- No 1:1 Folia region/threading behavior yet.
- The native terminal console supports `help`, `list`, `ops`, `op`, `deop`,
  `gamemode`, and `stop`; operators persist in `run/ops.txt`. There is no
  Minecraft command tree, tab completion, or Bukkit console dispatch yet.

## Recommended next steps

1. **Guard the baseline (P0.3–P0.5).** Track/validate the generated assets,
   add CI, and make the Java oracle dumps reproducible.
2. **Finish vegetation (P2.4/P2.5).** Add a two-registry selector resolver
   for placed-feature branches, port remaining aquatic plants, vines,
   mushrooms/huge fungi, and the remaining placement modifiers, then drain the
   new `WorldGenRegion` tick/block-entity sinks from the generator. Ore
   wiring/`OreVeinifier` (P2.3) still waits on feature-RNG parity.
   `feature_data.json` already has every definition.
3. **Real lighting (P3.5–P3.8).** Persisted sky/block light nibble arrays, the
   sky-light and block-light engines, then incremental light packets.
4. **Surface fidelity (P2.12 code landed).** Capture a Java frozen-ocean /
   iceberg fixture and thread `WorldGenerator.seed()` directly into
   `build_surface` so direct harnesses do not need the configured-generator
   fallback.
5. **Broaden the parity harness.** Capture all 256 columns (and more seed/chunk
   fixtures) from Java; the current fixture samples 16 columns.
6. **Then move to gameplay systems**: redstone, AI/damage, containers, online
   mode, NMS bridge.
